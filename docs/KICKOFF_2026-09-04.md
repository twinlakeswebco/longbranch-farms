## 1. What this project is

Long Branch Farms is a family farm in Grayson County, Kentucky (120 Long
Branch Drive, Leitchfield, KY 42754), established 2022, two employees,
serving Western Central Kentucky. Contact is Courtney Decker,
longbranchfarmsky@gmail.com, (270) 230-2339, prefers text. They sell
pasture-raised pork and grass-finished beef plus farm eggs, with chicken
planned as a future category. They are a Kentucky Proud member. Facebook is
their only live social channel.

The site is being rebuilt as a static, no-build marketing site: no server, no
database, no npm dependency the site itself needs at runtime. The registered
domain is `www.longbranch-farms.com`, not yet pointed at anything.

**Hosting decision, made:** Cloudflare Pages, on its free tier. Reasoning:
no bandwidth cap (relevant for a photo-heavy farm site), clean `www`
custom-domain HTTPS on the free tier, and zero-config support for the
directory-style clean routes and custom 404 page this repo already relies on
(GitHub Pages has more custom-domain friction; Vercel would need an added
`vercel.json` rewrite to get the same routing for free). **The site has not
been pushed to Cloudflare yet** — that happens only once the remaining tasks
below are done and the user says so explicitly. Do not deploy without being
asked.

## 2. Architecture

Hand-written HTML/CSS/vanilla-JS, no framework, no bundler, no `package.json`
for the site itself. Five real pages, each a subdirectory with its own
`index.html`, using **clean directory routes**:

```
/               -> index.html               (real file at repo root)
/about/         -> about/index.html
/contact/       -> contact/index.html
/privacy/       -> privacy/index.html
/terms/         -> terms/index.html
/404.html       -> served for any unmatched path, with a real 404 status
```

The old flat filenames (`about.html`, `contact.html`, `privacy.html`,
`terms.html`) still exist at the repo root, but only as tiny redirect stubs
(`<meta http-equiv="refresh">` + a JS `location.replace`) that send a visitor
on to the clean route. This exists so no old bookmark or external link
breaks. Do not delete the stubs and do not add content to them.

**Styling:** one shared `styles.css` (also referenced with page-scoped
`<style>` overrides in each page's `<head>` for that page's unique layout,
following the pattern `about/index.html` established). Design tokens live in
`:root`: colors `--soil` #1a1208, `--bark` #2e2010, `--moss` #3b4a2f,
`--moss-lt` #5a7048, `--hay` #c4a45a, `--hay-lt` #dfc07a, `--cream` #f5f0e8,
`--cream-dk` #ede5d5, `--white` #fdfaf4; fonts `--serif` (Playfair Display)
and `--sans` (Jost) from Google Fonts; motion `--ease`/`--dur`; layout
`--max-w` 1200px and `--side` (clamped gutter). Breakpoints are 960px and
660px. **Reuse these tokens and this class vocabulary** (flat kebab-case,
section-scoped prefixes like `product-card`, `fg-item`, `nav-drawer-*`) —
don't introduce a parallel system.

**JavaScript** is inline at the bottom of each page's `<body>`, not a
separate file, matching the site's no-build philosophy. It handles: the
footer year, the header's `.scrolled` state on scroll, a guarded
`IntersectionObserver` that drives the `.reveal` scroll-in animation (a
`prefers-reduced-motion` guard and a JS-disabled fallback both exist — see
§4), the product-tab switcher on the home page, and the mobile nav drawer
(hamburger + slide-in panel with focus trap, below 660px). `contact/index.html`
additionally has its own separate form-submission script.

**Images** live in `images/` (~47 MB, 185 files). Every photo used on the
page ships as WebP + JPEG fallback at 480/960/1440/1920px via `<picture>`
with `srcset`, generated by `tools/optimize-images.mjs` (needs `sharp`,
installed on demand with `npm i --no-save sharp` — not a committed
dependency). Full-bleed section backgrounds (hero, CTA bands) use CSS
`.bg-photo-N` classes with `image-set()` rather than inline styles, so they
can carry their own responsive `srcset`-equivalent. See `tools/README.md`
for exactly how to add a new photo — do not hand-write a new `<picture>`
block without reading it first, there's a manifest file
(`tools/image-manifest.json`) that has to stay in sync.

**Metadata:** every page has canonical URL, Open Graph, and Twitter card tags
pointed at `https://www.longbranch-farms.com`, plus a generated favicon set
and a 1200×630 social card (`images/social-card.jpg`). `index.html` carries
LocalBusiness + Farm JSON-LD with the real address, phone, `sameAs` links,
and a full `OfferCatalog` of every product and price — deliberately with **no
fabricated `geo`, opening hours, or ratings**, since none of that data is
real. `sitemap.xml` and `robots.txt` exist at the root; `robots.txt`
disallows `/docs/` (see §3).

**Contact form:** `contact/index.html` posts to Web3Forms
(`https://api.web3forms.com/submit`) with a live access key already in the
markup (`ba7f2a00-4e1f-42b2-8d2c-928367710458` — this is meant to be public,
it's a routing identifier, not a secret; see `README.md`). Free tier caps at
250 submissions/month; past that, submissions fail and the page shows the
farm's phone/email as a fallback so nobody hits a dead end. No account setup
needed — it's already configured and working.

## 3. Non-obvious things worth knowing before you touch anything

- **`docs/` is not site content.** It holds `KICKOFF_2026-09-04.md` (this
  file), the original intake PDF (`Website Project Intake Form - Courtney
  Decker.pdf`, which contains Courtney's personal phone/email/family
  details), and an earlier kickoff draft. It used to sit at the repo root
  and was reachable over HTTP before that was caught and fixed — it's now
  under `docs/` and disallowed in `robots.txt`. **`robots.txt` only deters
  well-behaved crawlers.** Whoever configures the Cloudflare Pages build
  must exclude `docs/` from the deploy (build output / ignored paths
  setting), or the PDF with Courtney's personal details will be publicly
  fetchable at a known URL again. This is the single most important
  deployment-config item in this whole brief.
- **Two commerce-related copy claims on `index.html` are currently false**
  and contradict `terms/index.html`: "Inventory updates in real time" and a
  "Sign up to be notified when new inventory drops" prompt with no signup
  mechanism behind it (`index.html` lines ~518 and ~657). `terms/index.html`
  correctly says nothing is binding until confirmed directly with the farm.
  This needs a decision, not a guess — see §5.
- **The mobile nav bar drops the "Order Now" pill.** Below 660px the
  hamburger drawer holds Order Now as a full-width button; the collapsed
  header bar only shows the hamburger and the logo, because the pill doesn't
  fit alongside them at 390px. This was flagged to the client as reversible
  on request. No answer received yet — leave as is unless told otherwise.
- **A handful of image derivatives are orphaned.** `photo-24-background`,
  `photo-6`, `photo-18`, `photo-20`, `photo-22`, `photo-25` each have unused
  `-480`/`-960` derivative files left over from when they were used as
  `<img>` rather than CSS backgrounds (backgrounds only reference the
  `-1440`/`-1920` sizes). `photo-26.jpeg` and `photo-27.jpeg` and their
  derivatives aren't referenced anywhere at all — deliberately kept on disk
  as ready-to-use spares. None of this breaks anything; it's a few hundred
  KB of repo bloat, not a functional bug. Low priority cleanup, not blocking
  launch.
- **The task tooling matters — use it, don't rebuild it.** `tools/` has
  survived a container restart once already and is fully committed:
  `dev-server.mjs` (dependency-free static server that mirrors clean-route +
  404 behavior locally), `e2e-check.mjs` (Playwright-driven full-site check,
  97 checks, currently 100% passing — run `node tools/e2e-check.mjs` after
  any change), `check-metadata.mjs` (head/JSON-LD-only checker),
  `optimize-images.mjs` + `generate-brand-assets.js` (image/icon
  generators). **Read `tools/README.md` before regenerating anything.**
  Playwright is resolved at runtime via `npm root -g`, not hardcoded to any
  one environment — if it's missing, `npm install -D playwright && npx
  playwright install chromium` once.

## 4. Verified-working, don't re-litigate

These were built, reviewed, and are passing 97/97 in the committed e2e
harness as of this brief. Confirm they still pass after any change
(`node tools/e2e-check.mjs`), but don't redesign them from scratch:

- All five pages load clean: no failed requests, no console errors, correct
  canonical tags, no horizontal overflow on mobile, descriptive alt text on
  every image.
- All four legacy flat-URL redirects work.
- The real 404 page returns an actual HTTP 404 status and is genuinely
  well-built (on-brand copy, an illustrated cow graphic, working links back
  home and to contact).
- Mobile nav drawer: opens, traps focus, closes on Escape/backdrop/link
  click, restores focus and scroll position.
- `prefers-reduced-motion: reduce` leaves all content visible — and
  separately, **content stays visible even with JavaScript entirely
  disabled** (progressive enhancement: `.reveal` is visible-by-default in
  CSS, JS opts into the hide-then-animate behavior, with a
  `DOMContentLoaded` backstop that un-hides everything if the
  `IntersectionObserver` never registers).
- `sitemap.xml` / `robots.txt` agree with the actual on-disk routes.
- Contact form validates client-side, submits via `fetch()` to Web3Forms,
  shows a real success/failure state, and degrades to a plain POST with
  farm contact info shown on failure.
- `privacy/index.html` and `terms/index.html` are genuine, specific
  documents (not template filler) reflecting the real form fields
  collected, the Web3Forms relay, the Google Fonts third-party request as
  the only other one made, real pricing, and an explicit "not
  USDA-certified organic" / no-health-claims stance.

## 6. Working conventions for this repo

Preserve the static, no-build architecture — this client has no developer
on staff, and every tool in `tools/` was written with that in mind (plain
narration in comments, explicit step-by-step instructions in `tools/README.md`,
no build step to explain). Match existing code style: flat kebab-case CSS
classes, inline JS at the bottom of `<body>` rather than separate files,
reuse of the design tokens in `:root`. Run `node tools/e2e-check.mjs` after
any change that touches HTML, CSS, or `images/`, and don't consider
something done until it's back to 0 failures. Commit to
`claude/longbranch-farms-kickoff-1rzulk` (or whatever branch the repo's
default branch has since become — check `git log` / GitHub before assuming
this branch name is still current) with clear messages; don't open a PR
unless asked; never push to Cloudflare without explicit instruction to do
so.
